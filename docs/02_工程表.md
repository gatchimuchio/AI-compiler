## 0. AICompiler主工程G0–G6と既存工程R0–R5の分離

- **主語＝AICompiler。目的＝既存機械語への最適なアクセス・操作・変換基盤を現行技術と規格で成立させる。** 既存の機械語を変更することは本工程の対象外。
- **新G0–G6＝2026-11-13のOwner訂正に基づく主工程の設計案。** 既存compiler・言語の変換基準と現実の実績の照合→AI専用操作記号の候補導出→実物比較・最適化→AICompiler基盤の採用。Ownerによる目的訂正は、本改訂文書の正式採用やGitHub書込許可を自動生成しない。
- **旧R0–R5＝AIC/0.2限定の初期実装・局所QC・QA記録。** 採用済みR2、R3 WIRED、R4 QC_OBSERVEDの履歴は事実として維持する。R3の成立を「操作記号が最適化された」「AICompilerが完成した」とは解釈しない。旧工程の細目・バッチB1–B49は本書後半・研究台帳・Git履歴に保存する。
- 工程の完成を、コミット数、資料数、試験数、カレンダー日数で代用しない。承認済み母集団と分母がなければ総合完成率は算定不能とし、状態別に報告する。

### 0.2 依存・施工順・帰還規則

1. **全体躯体先行。** まず既存AIC/0.2の実物producer→consumer経路を維持し、**自然言語元要求→AIによる記号生成・修正→既存machine object→consumer→計測証拠を単一課題で全接続**する。契約や接続点の文書だけではG1をWIREDとしない。局所的な追加調査・防御実装はどの上位Gateを成立させるのかを明示する。
2. G2の規格/実績照合とG3の評価方法設計はG1と並行できる。全言語/全版の調査完了は着手条件ではないが、比較対象を恣意的に閉じない。未調査・保留・不採用、一次規範・実装事実・測定結果を分離する。
3. G3の**未採用候補**は許可された実験範囲・隔離版でG4一気通貫させ、その後G5で実物QC・既存方式との比較を行い、G6で正式採否と対象別QAへ進める。評価前に候補の正式採用を要求して工程を循環停止させない。部品ごとの全面試運転を常態化しない。一方で権限・外部書込・安全・拒否は施工時に必要な局所検査を実施する。
4. 同一入力・意味・target・実行環境で比較できなければ、優位性や最適性を採用しない。尺度・下限・品質・scope変更は根拠・影響・反例を設計者が提示し、指示者/責任者であるOwnerが最終採否する。
5. 失敗と新証拠は応急patchだけで閉じず、要求・記号意味・変換規則・観測設計へ帰還する。元の判断と新判断は時点・根拠を付して別々に保持する。

## 1. 施工原則

以下の旧施工原則は**採用済みAIC/0.2初期経路の作業順**として保持し、AICompiler主工程G0–G6と取り違えない。

`全体の意味・責任境界の設計 → 一気通貫の変換実装 → 実物QC → 対象別QA → Owner最終公開判断`を基本とする。

小さな確認単位を積み上げること自体を成果としない。宣言した対象範囲について、AI文字列から規格適合の生成物まで、接続済みの仕事を成立させる。

全命令・全CPUの網羅率100%は初期β版の条件ではない。一方、対応を宣言した範囲の適合性は緩和しない。

「Codexを活用し、約1週間で限定対象のβ版を目指す」は**旧AIC/0.2のR0–R5に関する開発仮説**であり、AICompiler新G0–G6の確約済み納期や完成条件ではない。初期R2範囲はOwner採用済みだが、広いR1調査とR4対象QAの結果を踏まえてβ範囲・工程日数を再評価する。

## 4. 進捗・証拠分類

- `NOT_STARTED`：未着手
- `DESIGNED`：要求・仕様が定義された段階。実装済みではない
- `CODE_PRESENT`：コードは存在するが必要な実接続は未確認
- `WIRED`：入口から生成物まで実接続された段階。品質合格とは別
- `QC_OBSERVED`：対象実物の試験・解析結果が記録された段階
- `QA_SCOPED`：対象・条件を限定して必要な適合性が立証された段階
- `BLOCKED`：不整合・権限・証拠等により工程が進められない
- `OUT_OF_SCOPE`：現行受入対象外

未確認を`PASS`や`RELEASED`へ昇格させない。完了証拠はcommit、試験・監査記録、対応ターゲット、必要なリビジョン情報と対応づける。

## 5. 完了権限

Codexは**明示された作業範囲内**で調査、設計案、実装、検証、差分監査、ローカル保全を担当できる。**GitHubへのcommit/push・ref更新は文書作成・校正・main運用方針から自動許可されず、当該実行依頼で反映先と権限が明示された場合のみ行う。** 初期ターゲット・仕様の主要変更、品質要求の緩和、基盤の正式採用、β公開、商用化はOwner判断事項とする。
