# AI-compiler 統合仕様書 — 初期正本

- 版：`0.1-draft`
- 作成：2026-11-02
- 状態：**設計の基準文書。コンパイラ未実装・β版未リリース。**
- 主語：AI専用文字列表現を既存機械語に変換する**新規コンパイラ**

## 1. 目的

人間向け高級プログラミング言語を、AIによるプログラム生成から機械語実行までの**必須中間層**にしない。AIが操作する文字列表現を定義し、その意味を保存したまま、指定した実行環境の規格に適合する機械命令・生成物へ変換する。

本リポジトリは、過去の機械語再設計、命令運用最適化、メモリ方式再設計を継承しない独立プロジェクトである。

## 2. システム境界

`AI専用文字列 → 入力解釈・意味検査 → 制約処理・命令生成 → 機械命令／必要な実行形式`

| 領域 | 責任 |
|---|---|
| AI用入力形式 | 機械的に解釈可能な構文、意味、型／状態／操作の定義 |
| 新規コンパイラ | 入力意味の保存、未対応条件の拒否、対象規格への適合 |
| 既存規格 | ISA、ABI、OSインターフェース、実行形式、必要な環境条件 |
| 外部実行環境 | 自らが宣言する規格・条件に従った命令実行・ロード・サービス提供 |
| 検証・証拠 | 対象・版・前提・結果・未実行の識別、根拠を超えない主張 |

コンパイラ内部にどのような処理段階を置くかは、上の意味・責任境界を保持する限り自由に設計できる。既存IRや既存コンパイラへの依存を事前条件にしない。

## 3. 入力文字列の要求

- AIによる生成・編集・差分・再利用・検証の効率を評価対象とする。
- 人間の可読性、手書きしやすさ、既存言語との類似を必須条件としない。
- 文字列から操作・対象・関係・依存・状態変化・制約を一意に解釈できること。
- 曖昧な入力や非対応操作を正しく拒否できること。
- 文字数やトークン数の短さだけを唯一の最適化指標としない。
- 具体的な字句集合・構文・意味モデル・バージョン形式は未選定とする。

## 4. 対象規格・制約の取り込み

対象単位は、少なくとも`CPU/ISA + 拡張 + ABI + OSインターフェース + 実行形式 + 対応版`を明示する。対象外の環境を暗黙に保証しない。

1. LLVM、GCC、CompCert等の既存コンパイラから命令生成、環境適合、意味保存の実装知識を調査する。
2. 公式のISA・ABI・OS・実行形式仕様と照合する。
3. 規格要求、既存コンパイラの実装選択、未確認事項を分離して記録する。
4. 必要な規則を新規コンパイラへ統合し、対象版と出典を追跡可能にする。
5. 既存ソースコードを自動移植せず、第三者ライセンスと独立性を維持する。

## 5. 不変条件と拒否条件

- **意味保存：** 定義済み入力の意味と、生成命令の規定された作用を対応づける。
- **仕様適合：** 出力は宣言した実行条件に対応する規格に適合する。
- **決定性：** 同一の定義済み入力・構成・状態に対して、定義済みの変換結果が再現する。
- **境界保持：** コンパイラの義務と外部実行環境の義務を混同しない。
- **拒否の明確性：** 不明・非対応・矛盾・検査不能を成功へ変換しない。
- **品質の非緩和：** 対応範囲の縮小は可能だが、宣言した範囲の成立条件を弱めない。

## 6. 初期β版の受入条件（案）

初期対応範囲はOwnerが別途固定する。未選定のためCPU・OS・命令数や具体的な性能値を本書で創作しない。

受入に必要な証拠は、採用した入力文字列仕様、対象規格一覧、変換規則、対応／非対応表、意味保存・規格適合の検査結果、決定性、未実施項目、実行環境条件、生成物の所在である。

シミュレーションや参照実装との比較は、対象範囲の検証に使用できる。ただし実機未実施なら`実機未実施`と記載し、現物動作を保証したと主張しない。全CPU・全OSの検証を初期β版の受入条件に追加しない。

## 7. 未決定・非対象

| 項目 | 状態 |
|---|---|
| 初期ターゲットのCPU/OS/ABI/実行形式 | 未決定 |
| AI専用文字列の構文・意味形式 | 未決定 |
| コンパイラ本体の実装言語・ビルド方式 | 未決定 |
| 出力の直接機械語化／assembler・linker利用方法 | 未決定 |
| 具体的なβ版の日付と公開可否 | Owner判断待ち |

未決定事項の採用は実装開始前に記録する。`docs/02_工程表.md`と`docs/03_Codex施工指示書.md`は本書の目的・非対象を変更できない。
