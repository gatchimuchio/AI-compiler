## 1. 問いと適用範囲

宣言型の問い合わせや規則記述は、評価結果をどの種類の集合として定め、重複と順序をどの層で決めるか。また、再帰規則の結果をどのように成立させるか。この限定問いについて、W3C RecommendationであるSPARQL 1.1 Query LanguageとXQuery 3.1、製品文書としてのPostgreSQL 18、特定Datalog処理系であるSouffléの公式文書・論文を照合する。

PostgreSQL文書の記述をISO SQL規格全体へ、Souffléの実装文書をDatalog family全体へ外挿しない。SPARQL 1.1およびXQuery 3.1は選択した固定版の規範文書だけを根拠にする。SPARQL 1.2 Working Draft、他のquery言語、実装のローカル出力、実行性能、AIによる編集結果は今回評価しない。

## 3. AIC/0.2との比較

AIC/0.2の採用範囲は一つのu64引数から一つのu64を返すpure functionである。採用操作にrelation、RDF graph、XML node、複数結果collectionはなく、正常停止時の外部観測は単一戻り値である。CFG loopは表せるが、宣言されたquery結果集合のfixed-point計算を意味として採用したものではない。停止しないloopを入力不正として扱わない契約も保持する。

今回の比較では、次の点を同一視できない。

- **重複：** PostgreSQL SELECT ALLと通常のSPARQL SELECTは重複を保つ。SPARQL DISTINCTは厳密に除去し、REDUCEDは除去を許す。Soufflé relationはsetで同一tupleを重ねない。XQuery sequenceは重複を保持できるが、個別operatorの規則は別途定義される。
- **順序：** PostgreSQLの出力順はORDER BYなしでは未指定。SPARQL graph pattern結果はsequence化の前に順序を持たず、ORDER BY等のmodifierが後から順序を定める。XQueryはordered sequenceを値として持ち、ordering modeで一部のexpressionの順序保証を緩める。Souffléのrelationがsetであるという事実は、書き出すtupleの順番保証を意味しない。
- **再帰：** Souffléの記録されたtransitive-closure例は新規tupleを反復的に加え、fixed pointで結果relationを確定する。AICのbr/loopは実行制御であり、この集合成長・到達点の意味とは別である。

したがって、collectionを返すAI compilerを設計する場合、構文やloweringより前に、結果型、重複同一性、順序の保証、部分結果、再帰の収束・fuel/error/unknownを採用契約として決める必要がある。ここでの記述は将来設計に必要な問いを抽出した推論で、機能追加や採用の推奨ではない。

## 4. 今回得た限定所見

「queryは集合を返す」「結果は順序なし」「再帰ruleは必ず収束する」と一括りにできない。一次資料に結び付けた今回の候補だけでも、bag、多重度付きsolution、重複保持sequence、tuple setという異なる結果モデルがあり、順序は暗黙の実装結果ではなく明示modifier・ordering mode・未指定条件として扱われる。fixed-point停止も対象言語、domain、functor、規則の制約に依存する。

この所見はAIC/0.2の単一返却契約に矛盾を示さず、拡張の必要性を示すものでもない。AIがこれらの形式をより正確・効率的に生成または編集できるかは測っていない。性能、トークン長、成功率、修正回数について推論しない。
