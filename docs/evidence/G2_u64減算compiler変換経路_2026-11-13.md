# G2 u64 wrap減算のcompiler変換経路監査

- 記録ID：`G2-TRANSFORM-2026-11-13-01`
- 対象：既存比較の`aic_main(x) = (x - 1) mod 2^64`、Linux x86-64
- 判定：**AICの実装source、GCCのtree/RTL dump、rustcのLLVM IRを対応する既存machine codeまで追跡した限定観測。G2全体は未成立。**
- 事前条件・停止条件：[事前登録](../../experiments/g2-subwrap-transform-audit-2026-11-13/preregistration.md)
- 全コマンド、hash、raw dump/IR：[experiment record](../../experiments/g2-subwrap-transform-audit-2026-11-13/)

## 観測結果

| 経路 | 観測した変換 | 対応する`aic_main` |
|---|---|---|
| AIC/0.2 | parserは`sub.wrap.u64`を`InstructionKind::Sub`に変換し、interpreterは`u64::wrapping_sub`で意味を実装する。x86-64 emitterは引数と定数をstack slotに置き、左辺をloadして`subq rhs_slot(%rbp), %rax`、結果を別slotへstoreする。 | 既存objectは46 bytes。`movabs $1`、stack-slot load、`sub -0x10(%rbp),%rax`、result store、`leave; ret`。source実装は[parser](../../src/parser.rs#L361)、[interpreter](../../src/interpreter.rs#L111)、[x86-64 emitter](../../src/x86_64.rs#L135)。 |
| GCC 14.2.0 | 固定C sourceのtree-originalは`x + 18446744073709551615`と表示。optimized GIMPLEも同じ加算形。RTL expandでは`plus:DI`と`const_int -1`、final RTLでは同じ`plus:DI`を`*leadi`として選択する。 | dump付きobjectは既存objectとSHA-256が一致。disassemblyは`48 8d 47 ff c3`、すなわち`lea -0x1(%rdi),%rax; ret`（5 bytes）。 |
| rustc 1.99.1 / LLVM 23.1.1 | 固定Rust sourceの`wrapping_sub(1)`を含む出力LLVM IRは`%_0 = add i64 %x, -1`、`ret i64 %_0`。 | 同一invocationで出したobjectは既存objectとSHA-256が一致。disassemblyは`48 8d 47 ff c3`、すなわち`lea -0x1(%rdi),%rax; ret`（5 bytes）。 |

GCCには既存のC11 flagsに4つのdump出力指定だけを加えた。Rustでは既存のedition、target、crate、最適化、CPU、relocation、panic flagsを保ち、同じinvocationからobjectとLLVM IRを出した。診断付きobject SHA-256はGCC `1de6c84f1801ed6a8faf99d2a01078d29807a4792b453dce390075f9924c4429`、Rust `24d446b6223a22095261039aece4cd0abe6ef330188df36e61ec478efb4e5666`で、両方とも既存記録とbyte-for-byte一致した。したがってdump/IRは先行比較の実objectに対応する。

AIC実装sourceは元のcompiler build記録にあるrepository commit `12234aab847992d12e8a974ed2d1dd1777aa7bfa`と照合した。`src/ir.rs`, `src/parser.rs`, `src/interpreter.rs`, `src/x86_64.rs`, `src/validate.rs`, `Cargo.toml`, `Cargo.lock`のgit blobは基準main commit `e34e18d`と同一だった。GCC/Rustのsource、flags、既存disassembly/object hashは[前段の減算比較](G2_u64減算compiler比較_2026-11-13.md)に記録されている。

## 読み取り上の限界

- この一関数ではGCCとRustが同じ5-byte命令列を出し、AICは46-byte stack-slot形式を出した。GCC/Rustは`-O2`、AICには同等の最適化passがなく、これは品質や性能の順位ではない。
- GCC/RustのIRは各compiler版と指定条件で観測した中間出力であり、全版に固定の形式保証を与えない。AICのinterpreter経路は意味の参照であり、production codegen経路と同一処理ではない。
- 元の22入力consumer結果を再利用した。今回consumerやテストスイートを再実行せず、時間・throughput・CPU counterも測定していない。
- 一つの事後選択済み合成課題、一つのtargetに限る。長期運用、版/target全体の互換性、障害率・是正網羅、G2全体の完了、AIC形式の採用は示さない。
